1Overview

SDR++ Air Interface Analyzer (SDR++ AIA for short) is an experimental amateur radio edition of SDR++ for analysing the air interface of radio networks. It currently contains TETRA (module TETRA Analyzer): the program receives with an SDR, decodes TETRA transmissions and measures the signal quality the way you know it from a measuring instrument – from the constellation diagram to the coverage map. It is operated through a single surface like a measuring instrument, the instrument view (chapter 3).

Explicitly for experimental amateur radio purposesThe program is intended exclusively for experimental amateur radio purposes – for experiments, self-training and technical investigations in the amateur radio service. It is not a calibrated measuring instrument and is not intended for commercial, professional or public-authority use.

What the program does

  • Demodulation and decoding of TETRA (π/4-DQPSK, 18 ksym/s) with an 8-point constellation and ETSI tolerances.
  • Modulation quality: MER, EVM, I/Q offset, I/Q imbalance, phase/amplitude error, carrier and symbol clock offset, BER, CRC statistics.
  • Network information: cell, neighbour cells, network time, timeslot usage.
  • Stations and traffic in amateur radio mode with call signs (radioid.net) and talk groups.
  • TX analysis: spectrum, adjacent channel power, occupied bandwidth, shoulders, carrier leakage.
  • Burst analysis of handhelds: ramps, length, ripple, time mask, ramp spectrum, noise on the uplink.
  • Multipath, frequency stability (Allan deviation) and reception limit.
  • Long-term monitoring: trends up to 24 h, CSV logs, alarms, measurement report.
  • Coverage measurement with a GPS mouse: map of the drive in the program (optionally with a map background, also offline), export for Google Earth (KMZ/KML) and OpenStreetMap.
  • Several carriers compared at the same time.

How the program works

The SDR delivers a wide I/Q data stream. From it the program cuts several narrow “taps” (VFOs): the TETRA VFO for demodulator and decoder and – only when needed – further, invisible taps for TX analysis, burst analysis, multipath and additional carriers. In the instrument view TX analysis, burst analysis and multipath run only while their view is shown; in the mode Alignment the TX analysis runs automatically. All taps must lie within the bandwidth of the SDR. Every tap costs processing time at the full sample rate, so from v0.22.2 TX analysis, modulation accuracy and multipath share one analysis tap (288 kS/s, halved exactly to 144 kS/s for the latter two – passband ripple 0.0002 dB, stopband attenuation 100 dB; the results are the same as with separate taps).

2Installation and first start

Windows

  1. Download the ZIP file SDRPP-AIA_v…_windows_x64.zip and extract it completely into a folder of its own (do not start it from inside the ZIP).
  2. Start sdrpp.exe. Because the program is not signed, Windows SmartScreen warns: More info → Run anyway. If the browser already blocks the download, explicitly keep the file in the download list.
  3. Settings, logs and name lists are kept in the same folder as sdrpp.exe. For an update, extract the new folder next to the old one; the configuration (config.json, *_config.json) can be copied over.

3The user interface

The program is operated through a single surface, like a measuring instrument: the instrument view. There is no SDR menu column and no menu button any more; everything that used to be in the menu is in the Settings. The texts of the instrument view exist in English (default) and German (Settings → Display & operation → Language). Texts without a translation – the sections from SDR++ itself (source, audio, display, modules) and the contents of the views – stay English in both languages.

Layout

  • Top bar: start/stop of the SDR, volume and frequency display (mouse wheel or click on the digits). There is exactly one VFO, the TETRA VFO, and only normal tuning: a click into the waterfall puts the VFO onto that frequency, the centre of the SDR stays where it is. Therefore the VFO selector, Lock, the centre-tuning button (it would put the channel onto the DC spike in the middle of the band) and the SNR meter are not shown here; level and MER are in the status bar.
  • Status bar below it: the most important values at a glance (3.1).
  • Content column on the far left, with a fixed width: what belongs to the mode – audio and compact cell data (Monitor), measured values with limits, short trends and last analysis results (Measure), large value tiles (Drive test), error components and procedure (Alignment). Its width follows the content in the chosen language and does not change while measuring.
  • Main view in the middle: spectrum and waterfall or the chosen view (constellation, TX spectrum, burst, carriers, trends, multipath, map of the drive test, alignment). The sliders Zoom, Max and Min are only shown while the waterfall is visible.
  • Strip below the main view, only in the mode Monitor: in amateur radio mode Stations, Groups and Traffic (chapter 8), in ETSI mode network and cell (chapter 7). Its height is set with the divider above it.
  • Softkey column on the right, as wide as its longest text in the chosen language: the four modes at the top, below them the views or softkeys of the mode, at the very bottom RF / Gain and Settings.
  • Message line at the bottom: notes and warnings, log state and clock on the right (3.1).

Mode, view and language are kept over a restart.

Alignment

This mode is meant for aligning a transmitter: you adjust something at the transmitter and see at once whether it gets better or worse. The main view shows four meters with limit and scale:

  • Freq. error – limit base station ±0.2 ppm of the frequency (±0.1 ppm above 520 MHz), shown in Hz; mobile station ±100 Hz (EN 300 394-1 7.3.2.2). Scale ±2 × limit.
  • EVM rms – limit 10 %, scale 0–15 %.
  • Residual carrier – limit −26 dB (5 %), scale −60 … −16 dB.
  • Adjacent channel – adjacent channel power at ±25 kHz, worse side; limit −60 dBc, scale −80 … −50 dBc.

The value is green inside the good zone (green band) and red outside it. If it lies beyond the scale, an arrow at that end of the scale points in its direction. The dashed blue line is the reference; with Delta to reference ON (default) the change against the reference is shown in blue on the right (“to ref.”).

  • Set reference stores the current values (frequency error, EVM, residual carrier, phase and amplitude error, adjacent channel).
  • Hold freezes frequency error, EVM, residual carrier, EVM peak, symbol clock and level at the moment it is switched on. Adjacent channel, phase and amplitude error and IRR keep running.
  • Limits: base station / Limits: mobile station switches the frequency limit (the softkey shows the one in force).
  • The content column shows the Error components (phase error, amplitude error, EVM peak, I/Q imbalance, symbol clock, level; with a running burst analysis also the uplink noise) and the Procedure: 1 Set reference, 2 Adjust, 3 Read the delta. If the frequency reference is set to “internal”, a note reminds you that the frequency error contains the error of your own SDR (indicative).
“receiver limited” at the adjacent channelThe adjacent channel measurement is limited by the dynamic range of the SDR: what the receiver itself puts into the adjacent channel (noise, phase noise, ADC) looks like emission of the transmitter. If the measured value is less than 3 dB above this measurement floor, it is shown grey and marked receiver limited – the transmitter may be better. Remedy: set the level with an attenuator so that the SDR works close to full scale (without overload), and store the noise floor with Store floor in the view TX spectrum (ACP) (chapter 9). In Last analysis results such a value carries a “*”.

4Setting up the SDR

The SDR itself (device, sample rate, gain, frequency correction) is set in the RF / Gain window; the same is under Settings → SDR & calibration → SDR source. The controls of the TETRA Analyzer (AFC, Lock VFO, Snap to carrier, Auto RF gain, SDR line) are below it under AFC & level; in the classic layout in the section Measurements.

Basic rules

  • Sample rate: 1–2.4 MS/s are enough for one carrier. For uplink and downlink at the same time and for additional carriers the bandwidth must cover all frequencies – for 70 cm repeaters with 9.4 MHz duplex spacing that means ≥ 10 MS/s; otherwise make the measurements one after the other.
  • Do not put the centre on the carrier: the DC component of the SDR lies in the middle of the band. Tune the TETRA carrier at least ~100 kHz away from it, otherwise it falsifies the I/Q offset and carrier leakage. In the modes Measure and Alignment the message line warns when the TETRA VFO is less than 15 kHz from the centre.
  • Level: as much gain as needed, as little as possible. Auto RF gain looks for the best signal-to-noise ratio: it steps up by 3 dB while the ratio still improves and steps back once the noise floor only rises with the gain. It goes down at once when any signal in the whole SDR band (not only TETRA) reaches the ADC limit. The Band line shows this peak and the ratio.
  • Gain mode (from v0.20.4): Level and hold finds the best step once and then keeps it fixed – all results of a measurement series are taken with the same receiver settings. If the ADC nears clipping or the ratio drops by more than 6 dB, a note appears; Re-level levels again. Follow adjusts continuously. Automatic (GPS) (default) follows while moving (GPS above 5 km/h, averaged over 10 s) and holds after 30 s standing still or without GPS. With a level calibration (dBm) it may follow as well: the program remembers the gain when the calibration is entered and corrects the level by the difference from the SDR's gain table (about ±1 dB, shown as "gain-corrected"). Older calibrations without a remembered gain ask to be entered again; until then it holds.
  • Lock VFO: the mouse no longer tunes the TETRA VFO – clicking or dragging in the spectrum and waterfall only moves the view, the wheel and the arrow keys do nothing. AFC and frequency entry still work. From v0.22.2 the VFO also keeps its frequency when the view is dragged past the band edge and the SDR is retuned; the view stops before the VFO would leave the band.
  • Snap to carrier (from v0.22.2, on by default): a click or drag that tunes the TETRA VFO ends on the centre of the strongest carrier within ±25 kHz – also with the view zoomed out. The program evaluates a spectrum of the raw samples around the click and puts the frequency on the 6.25 kHz raster when it is within 1 kHz of it. Without a recognisable carrier (at least 8 dB above the noise) the VFO stays where it is. Workflow: click the carrier, then tick Lock VFO.
  • SDR line: shows source and sample rate and recommends a range (tooltip). Recommended view sets the centre to 440 MHz − 0.45 × sample rate so the band ends just above 440 MHz; this also happens automatically at the very first start.
  • Gain control locked: while Auto RF gain is active, the gain control of the SDR source is locked ("Locked by TETRA Auto RF gain"). Release switches the automatic gain off and frees the control.
  • Warm-up: wait 10–15 minutes after switching on before calibrating the frequency or measuring stability.

Calibration

Under Settings → SDR & calibration → Calibration & reference (classic layout: section Measurements), Carrier vs. SYSINFO shows how far the received carrier deviates from the frequency the base station itself announces. Calibrate SDR sets the frequency correction of the SDR so that this deviation disappears. In the measurement column, the line Carrier error shows the same value. The manual frequency correction (e.g. Freq. corr. (ppb)) is under RF / Gain.

Calibrate only on a trusted cellThe value contains the error of the base station and of the SDR. Only calibrate on a station whose frequency you know (GPS-disciplined, or measured beforehand with a reference-locked SDR), and only after the warm-up.

USRP: calibrating the internal clock against the reference

With the clock source external (10 MHz input) or gpsdo the USRP needs no correction: Freq. corr. (ppb) is locked and shows external reference - no correction needed. With the internal clock the field is editable; the value is stored per device (serial number). The internal oscillator can be measured against the reference once it is connected:

  1. Select the clock source external or gpsdo, start the SDR and tune the TETRA Analyzer to any TETRA carrier until it is locked. Its frequency accuracy does not matter: only the difference between the two clocks is measured.
  2. Press Calibrate internal clock against reference in the USRP source (RF / Gain). The TETRA Analyzer measures the carrier for 6 s with the reference, switches the USRP to its internal clock, waits for the PLL and the decoder to lock again (4 s after lock, at most 20 s), measures again for 6 s, and switches back to the reference.
  3. The difference is the error of the internal oscillator; it is stored for this device (serial number) as Freq. corr. (ppb), shown with calibrated against reference and the date and time. From then on it is applied whenever the internal clock is selected. Entering a value by hand (or Calibrate SDR) replaces it.
  4. The calibration aborts cleanly – back on the reference, nothing stored – if the lock is lost, the carrier is unstable, the result is implausible (more than 20 ppm) or Cancel calibration is pressed. The status line below the button tells why.
Warm up firstThe internal TCXO drifts with temperature. Calibrate only after 20–30 minutes of operation, in the usual surroundings; repeat the calibration if the temperature changes a lot.

Constellation

Mode Measure, view Constellation. π/4-DQPSK has eight target points (softkey 8 points (pi/4)) – switched off, they are folded onto four. The rings show the ETSI limits (EVM 10 % rms, 30 % peak). The points turn green when the measured EVM is within the limit, red otherwise.

Remove I/Q offset removes a carrier leakage of the transmitter (or the DC component of the receiver) from the display; EVM and colour of the points then apply without it. The residual carrier is still shown with the measured values.

Listen to – which call is played

Always one call is played: the ETSI speech codec has a single state, two calls decoded in turn would mix. Only the chosen timeslot goes through the codec. Listen to is in the mode Monitor in the content column under Audio:

  • Auto – the first timeslot with speech in the TDMA frame.
  • One timeslot – only TS1 … TS4.
  • Priority list – scanner: the first group or station of the list that is talking now; a higher one interrupts a lower one. List... edits the list (order, delete, enter a GSSI/ISSI); Other calls when no listed one is active plays the other calls otherwise. New entries are a group or a station (Group | Station). Easier: right-click a GSSI or ISSI in the stations strip → Listen to this one (top of the priority list) or Add to the end of the priority list; list entries carry a “*” there.

Which group/station uses which timeslot comes from the channel allocation of the network at call setup (readable in clear signalling only).

Muting encrypted calls: softkey Mute encrypted (default ON; classic layout: checkbox Mute encrypted). The program cannot decode encrypted speech, it would only be noise. The state is kept per timeslot for the current call and linked by the call identifier: the call setup (D-SETUP, D-CONNECT) says whether the call is encrypted, D-TX-GRANTED of the same call confirms it, D-RELEASE/D-DISCONNECT ends it. A long call with many transmissions thus keeps its state.

  • Unknown stays muted (fail-safe): if the call setup was not received – the call started before decoding began, or the block had a CRC error – the timeslot stays muted until a call setup assigns it: the late-entry setup the network repeats for ongoing group calls (if the cell sends late entry), or the next call. Playing then shows encryption unknown - muted, for an encrypted call encrypted call - muted.
  • Play anyway appears only while a call is muted because its encryption is unknown. It releases exactly these timeslots until there has been no traffic on them for 10 s or a call setup clears the state; after that the program decides by itself again.
  • Timeout: if no signalling of a call is received for more than 320 s (longest transmission T311 = 300 s per EN 300 392-2 plus a margin), its timeslot counts as unknown again – this way a missed release cannot keep a timeslot audible.

Playing shows the transmission (one PTT) heard now as a fixed block:

  • What: timeslot and group with name. Who: talker (ISSI and call sign if known).
  • Duration: time since the first speech burst of this talker. The call time over all transmissions of the group is in the tooltip.
  • Frames OK: share of speech bursts without CRC error in the transmission (bad frame indicator of the channel decoding, EN 300 395-2); green from 98 %, yellow from 90 %. Blocks stolen for signalling are not counted as errors. A low value explains poor sounding speech by the reception.
  • Hang time 2 s: the block stays until no speech burst came for 2 s – short gaps for signalling do not interrupt it. Afterwards it shows the last transmission in grey (“last:”, “… s ago”).
  • Arrangement: one line when wide, two in the content column or the normal menu (what with duration on top, who with frames OK below), three when narrow. Numbers are right-aligned, the height stays the same, also when nothing is played.
  • Right-click: add the group or the talker to the priority list. Encrypted, muted calls appear in orange as “encrypted call – muted”.

Encryption (indication only)

The program decrypts nothing; the encryption code of osmo-tetra is removed. In the cell information (chapter 7; softkey Cell details), Air interface encryption shows whether the cell offers air interface encryption and whether a CCK is in use (security class 3). Encrypted messages appear in Traffic as encrypted – not decoded; stations with encrypted traffic carry an “E” in the TS column. If the cell sends the extended services in SYSINFO, Security shows the security information per EN 300 392-7 V3.5.1 (A.8.77): authentication required or not, support of class 1 MS, class 2 (with SCK number) or class 3. 9TX analysis (spectrum)

Mode Measure, view TX spectrum (ACP). The analysis starts with the view (softkey Analysis: ON) and stops when the view is left; in the classic layout the checkbox Run analysis (250 kHz tap) switches it. It uses the shared 250 kHz wide analysis tap around the channel and measures:

  • Channel power through the TETRA filter.
  • ACP at ±25, ±50, ±75 kHz in dBc, with (adjustable) limits.
  • Occupied BW (99 %) and −26 dB bandwidth compared with the ideal TETRA spectrum.
  • Shoulders and edge slope – shoulders point to non-linearity of the power amplifier.
  • Carrier line – carrier leakage as a spectral line.

With a large I/Q offset, a diagnosis line names the likely cause: if carrier line and I/Q offset agree and the receiver's DC is far enough away, it is carrier leakage of the transmitter (check its LO/DC calibration).

Operation:

  • RBW: resolution bandwidth 122 Hz (4k FFT), 61 Hz (8k) or 31 Hz (16k). Finer = more accurate shoulders, but slower.
  • Avg (1…100): number of averaged spectra. Reset average restarts the averaging, e.g. after a change at the transmitter.
  • Store floor stores the current averaged spectrum as the measurement floor of the receiver: first switch the transmitter off or terminate the SDR input with 50 Ω, same gain and sample rate. Values close to this floor are marked grey. Without a stored floor the noise far from the carrier serves as an estimate. Clear floor discards it.
  • ACP limits (expand): limits at 25, 50 and 75 kHz in dBc, with presets from EN 300 394-1 7.1.3.2: BS / MS class 1-3 (table 7.2: −60/−70/−70 dBc), MS class 4/4L (table 7.1: −55/−70/−70 dBc), > 700 MHz (table 7.3: −55/−65/−65 dBc). The average power over the useful part is measured through the TETRA filter; the own floor of the test set-up must be below −70/−80/−80 dBc (B.1.2.3).

The softkey Channel raster (default ON; classic layout: 25 kHz channel raster in the spectrum) draws dashed channel boundaries at ±12.5 and ±37.5 kHz around the TETRA channel in the spectrum above the waterfall. The spectrum above the waterfall can be averaged under Settings → Display & operation → Display → Spectrum averaging: time constant in seconds (after this time a step has reached 63 %, after five times this time 99 %); Power averages the power and shows correct levels, Log (dB) averages the dB values (noise then appears about 2.5 dB too low). Max hold shows a second trace with the maximum that decays at the set rate in dB/s (0 = hold until switched off). For measurements this view with Avg is the right tool.

The ACP table shows for each spacing (±25/50/75 kHz) the lower and upper value, the limit and the measurement floor. A “*” marks values less than 3 dB above the measurement floor – the true value may be lower. If the channel is closer than 15 kHz to the centre frequency of the SDR, a red line warns: the receiver's DC offset then falsifies I/Q offset and carrier leakage; tune the SDR at least ~100 kHz away.

Limits of the measurementThe adjacent channel measurement is limited by the dynamic range and phase noise of the SDR – typically −60 to −70 dBc. For values close to the limit, use a strong, clean signal and a low gain, bring the level close to full scale with an attenuator and store the measurement floor. Values less than 3 dB above the floor are marked by the program (see “receiver limited”, 3.2).

12Burst analysis (uplink)

Handhelds transmit in bursts – short transmissions in their timeslot. The burst analysis measures them through a 25 kHz channel filter. The frequency is the uplink from the network information (Uplink (SYSINFO)), a manual frequency or the TETRA VFO (e.g. a base station in discontinuous mode).

Burst shape and time mask

  • Length (−3 dB): burst length; nominal 231 symbols (12.8 ms) for normal, 103 for half bursts.
  • Ramp up/down: time from −20 to −1 dBc and back.
  • Ripple: ripple in the useful part (averaged).
  • Outside the burst: power before and after the burst (dBc) – limited by the receiver noise (“at the floor”).

The chart shows the shape averaged over the last bursts with the Time mask (red).

Operation

  1. Choose the mode Measure, view Burst (uplink): the analysis starts (softkey Analysis: ON) and stops when the view is left; in the classic layout the checkbox Run burst analysis switches it. Choose the frequency with the segmented buttons: Uplink (SYSINFO) | Manual frequency (enter MHz) | TETRA VFO. The Frequency line shows what is measured.
  2. Averages (1…500, default 200 per EN 300 394-1 8.4) sets how many bursts are averaged; Reset discards the bursts so far.
  3. The softkeys Overload check (default OFF) and Ramp spectrum (default ON) switch the two additional measurements on (both cost CPU time); in the classic layout the chips after Also:.
  4. Reading: Floor and peak (noise floor and peak in the channel), Bursts (counted full and half bursts, bursts/s), then Burst power and the shape values. Green = within the mask, red = outside. “No bursts detected”: nobody transmits; “continuous carrier”: a steady carrier instead of bursts.
  5. With Overload check on, the program opens a second, sample-aligned tap on the TETRA VFO (downlink of the same cell; it must be inside the SDR span and more than 50 kHz away from the burst frequency) and tests whether the downlink gets weaker during the bursts (more than 1 dB = receiver overloaded, results invalid). The Linearity check (below) is always available and needs no downlink.

Time mask (expand): Check against EN 300 392-2 6.4.5 (default on) checks against the standard (see below); Station selects Mobile station (uplink) or Base station, discontinuous; MS power class 4 / 4L relaxes the switching transient limit; MS transmit power known with a dBm value converts the absolute limits to dBc. Without the standard check the own mask applies: Ripple +- dB (default ±1 dB), Outside dBc (−40 dBc) and Ramp max. sym (rise/fall −20…−1 dBc within at most 5 symbols) – guide values for your own comparison.

Measuring the uplink alone and checking linearity

The figures the standard defines for the mobile – power versus time, time mask, switching transients, power outside the burst, adjacent channel power and modulation accuracy – concern the transmitted signal only; they do not need the downlink. So the SDR can run on the uplink alone with a low sample rate (1–2 MS/s, source Manual frequency). This relieves the computer and avoids the dynamic range problem: the repeater a few kilometres away is weak, the nearby radio 60–80 dB stronger – more than a 12-bit converter handles at the same time.

Without the downlink, overload is checked with the Linearity check (the usual lab method): hold the receiver gain (Level and hold), press Note level, insert the set attenuation in addition in front of the SDR (default 10 dB, external attenuator), press Attenuator added. After 20 bursts the program compares (Check again restarts the check): if the burst power drops by the attenuation ±0.5 dB, the receiver is linear. If it drops less, it was overloaded before – leave the attenuation in and check again with one more step. If it drops more, the radio changed its power (power control) or the attenuation value is wrong. Lowering the software gain is no substitute: it only tests the stages after the attenuator.

Transmit power of the radio: the absolute limits of the standard (−36 dBm for the power outside the burst and for switching transients) refer to the antenna connector of the radio. Over the air the received level says nothing about it (path loss). Under Time mask → MS transmit power known enter the transmit power (e.g. 12.6 dBm for 18 mW, 32.6 dBm for 1.8 W); the dBc limit follows as Lmin = max(−70 dBc; −36 dBm − P). Without an entry −70 dBc applies.

Ramp spectrum (switching transients)

Most of the interference in the adjacent channels is produced when switching on and off. Ramp spectrum measures the channel power at −50, −25, ±0, +25, +50 kHz in 1.8 ms windows during the ramp-up, in the middle and during the ramp-down, relative to the middle. Orange: ramp more than 6 dB above the middle (splatter).

As in the standard (from v0.21.1): the line Switching transients (peak, ±25 kHz) measures, as in EN 300 394-1 7.1.4, the peak power through the TETRA filter at −25 and +25 kHz over the whole ramp-up and ramp-down period, with maximum hold since the last reset. Limit −50 dBc, for MS power classes 4/4L −45 dBc (selection under Time mask). The envelope of the burst analysis now runs through the TETRA filter (root raised cosine 0.35, 33 symbols) as EN 300 392-2 6.4.5 requires. Time mask checks table 6.8 / figure 6.3: ramp-up within t1 (16 symbols), ramp-down within t3 (15 symbols), at most +6 dBc during t1 and +3 dBc during t3, outside Lmin (MS −70 dBc or −36 dBm, BS −40 dBc). If the measurement floor is above Lmin, this is shown. Default averaging: 200 bursts (EN 300 394-1 8.4). For the adjacent channel power, ACP limits offers presets per tables 7.1–7.3.

Noise on the uplink

Noise between bursts measures the power in the channel while nobody transmits – on the uplink of a repeater that is its receive noise and interference. Below it, Noise history shows the history (range under Span, up to 24 h) – interferers that make the repeater “deaf” stand out; an alarm can react to it. Without gaps between bursts (steady carrier) there is no value.

Never connect a transmitter directlyNever connect a handheld to the SDR without sufficient attenuation (e.g. 60–70 dB, power-rated attenuator). For measurements an antenna a few metres away is usually enough.

13Multipath

Mode Measure, view Multipath (classic layout: section Multipath (downlink), checkbox Run multipath analysis). The analysis starts with the view (softkey Analysis) and stops when it is left. Every downlink burst contains a known training sequence. From it, the analysis estimates the channel impulse response and averages it into a power delay profile. The comparison with the profile of an ideal signal (green) reveals echoes:

  • Strongest echo: delay (µs), detour (km) and level of the strongest echo above −15 dB.
  • Extra delay spread: additional delay spread compared with the ideal signal.

Echoes from about 55 µs (17 km detour) to 222 µs are detected; shorter ones only widen the main path. TETRA receivers cope with echoes up to about ¼ symbol (14 µs) without loss. Averaging: 2 s for drives, 60 s or unlimited for fixed locations.

17Measurement scenarios

The following procedures are suggestions – they can be combined freely.

A · Transmitter quality of a repeater (downlink)

Goal: modulation quality and spectrum of the base station · duration: 10 minutes
  1. SDR in line of sight or with a directional antenna; signal well above the noise (stable MER display). Band centre ≥ 100 kHz away from the carrier.
  2. Let Auto RF gain settle, then read the measured values in the mode Measure: EVM, error phase / ampl., residual carrier, IRR, MER (status bar).
  3. Choose the view TX spectrum (ACP) (the analysis starts); beforehand Store floor with the transmitter off (or the input terminated).
  4. Assess ACP, occupied bandwidth, shoulders and carrier leakage; for values close to the measurement limit (“*”, receiver limited) bring the level close to full scale with an attenuator and store the measurement floor again.
  5. Create report for documentation.

Interpretation: high residual carrier with poor MER but good MER w/o offset (classic layout) or good EVM with Remove I/Q offset → carrier leakage of the modulator. Much phase error → phase noise of the oscillator. Pronounced shoulders → overdriven power amplifier.

B · Frequency accuracy of the base station

Goal: frequency error in ppb and stability · requires a GPS-disciplined SDR (e.g. Pluto+ with 10 MHz)
  1. Connect the SDR to the reference, warm up for at least 15 minutes.
  2. Set the frequency reference to “External 10 MHz” (Frequency reference under Settings → SDR & calibration → Calibration & reference, 3.3), then watch Carrier error in the mode Measure (target: ±200 ppb according to ETSI).
  3. View Trends → tab Frequency stability: let it run for at least one hour; read the Allan deviation.
  4. If required, let the measurement run overnight (CSV log) and open the log later.

C · Coverage measurement with heatmap

Goal: coverage map and practical reception limit
  1. Calibrate the level (dBm), Auto RF gain off; mode Drive test: connect GPS (GPS...), set the cell site (Cell site...), lock the cell (chapter 16). On the road without network: save a map of the area beforehand (Saved maps...).
  2. Start the CSV log, drive through the area – also to the edge of the coverage. The map of the drive test shows where you have already measured.
  3. Load the log in the view Trends with Open log... → tab Level vs. quality: read the reception limit and set the CRC limit accordingly.
  4. In the drive test open the drive with Load drive..., compare the map values Level and Quality and Export map: the KMZ file contains all map values as folders. Measure gaps (black) again specifically.

D · Long-term monitoring of a repeater

Goal: detect outages and degradations · duration: days
  1. Set up a fixed receiver with stable gain (Auto RF gain off).
  2. Settings → Limits & alarms: switch on level, MER, CRC and sync, hold time e.g. 30 s, Start CSV log on alarm.
  3. Optionally the burst analysis on the uplink for the noise level and its alarm (it runs only while the view Burst (uplink) is shown; for continuous operation stay in this view in the mode Measure).
  4. Look at the trends daily or open the log; in case of anomalies Create report.

E · Checking a handheld (uplink)

Goal: burst shape, time mask and splatter of a radio
  1. Set the SDR to the uplink only (1–2 MS/s), attenuator in front of the SDR (18 mW at 1–3 m: about 20–35 dB). Source Manual frequency with the uplink frequency; hold the gain (Level and hold).
  2. Choose the view Burst (uplink), Ramp spectrum ON; enter the transmit power of the radio under Time mask.
  3. Run the Linearity check; the figures are valid only once it reports “OK – linear”.
  4. Make a few transmissions with the radio (or send an SDS); receiver close to the radio (mind the attenuation!).
  5. Check burst length, ramps, ripple and mask; look at the ramp spectrum for splatter.

F · Hunting interference at the repeater receiver

Goal: detect intermittent interferers on the uplink
  1. Run the burst analysis on the uplink (view Burst (uplink)); note Noise between bursts as baseline.
  2. Set the alarm “UL noise above” a few dB above the baseline.
  3. Look for time patterns in the history (Noise history, 24 h) – e.g. daily times point to devices in the neighbourhood.

G · Comparing neighbour cells

  1. Decoder on one cell; neighbour cells appear under Cell details → Network broadcast & neighbour cells.
  2. View Carriers → Add neighbour cells.
  3. Compare level differences and MER over time (e.g. from the same location at different times of day).

H · Multipath at a new location

  1. Decoder locked, MER above 15 dB.
  2. View Multipath with Averaging 60 s; note echoes and delay spread.
  3. On drives choose 2 s and compare places with strong echoes with poor MER.

Checking USB and lost samples

Poor MER with a clean spectrum and a rising Re-locks with slip count means samples are missing. Narrow it down like this (PlutoSDR on Linux; quit SDR++ first):

  1. Device and USB alone: set the rate and read a fixed number of samples while timing it. 40 million samples at 4 MS/s must take 10.0 s: 
    iio_attr -u usb: -c ad9361-phy voltage0 sampling_frequency 4000000
time iio_readdev -u usb: -b 262144 -s 40000000 cf-ad9361-lpc voltage0 voltage1 > /dev/null
    Clearly more than 10 s means the Pluto drops data (USB, cable, power). Test the limit with 7 MS/s and -s 70000000.
  2. Connection: keep sudo dmesg -w running. disconnect or error -71 point to the cable, a contact or too little power (connect the Pluto's second USB port to a power supply). lsusb -t shows which devices share the bus (webcam, card reader).
  3. In the program: press Reset statistics and let it run for two minutes. Overflows under RF / Gain must stay at 0, and the message line must not show Samples lost (USB / CPU). If it rises only here, the computer cannot keep up: close screen recording and other programs, lower the sample rate.
